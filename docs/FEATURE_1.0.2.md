# 1.0.2：原生搜索入口与设置页

## 使用流程

默认按 Ctrl+Shift+F 直接打开 IDEA 的 Find in Files。需要组合条件时，点击原生窗口标题下的“增强搜索…”按钮。

原生搜索窗口在后台保留；增强条件确认后原位更新其查询，不替换原生搜索模型，避免原生确认按钮仍执行旧查询。搜索范围、目录、递归、文件过滤继续采用进入增强模式时的当前值。

取消增强条件或者点击“普通搜索…”返回同一个原生窗口，保留原有输入及过滤条件。增强窗口打开期间原生窗口的失焦自动关闭被暂时阻止；退出时恢复。

原生普通文本会作为一个字面文本条件带入，大小写和完整词选项与原生保持一致。已有正则不会自动逆向拆分，增强草稿仍保存在当前项目内。

## 设置页

**Settings → Tools → 搜索增强**，应用级配置，所有项目共用：

| 选项 | 默认 | 行为 |
| --- | --- | --- |
| Ctrl+Shift+F 默认打开 | 先打开 IDEA 原生搜索窗口 | 也可改为直接打开增强条件窗口 |
| 原生窗口显示“增强搜索…”按钮 | 开启 | 取消后原生窗口不追加增强入口 |

配置存储：`options/SearchEnhancePreferences.xml`。设置页面 ID：`search.enhance.preferences`。修改应用后，在下次打开搜索窗口时生效；Ctrl+F 始终保留原生功能。

## 实现边界与性能

IDEA 2023.3.8 的原生 Find in Files 没有可追加标题栏按钮的 Action Group。插件在实际原生 `FindPopupPanel` 标题下追加一行入口，只调用该版公开可访问的面板方法；不反射其私有字段、不替换原生组件或结果窗口。

入口采用组件显示事件监听和面板标记去重，不使用轮询计时器，也不扫描项目文件。监听器由应用服务释放，按钮行随原生面板的 Disposable 清理。直接进入增强模式的偏好继续通过 FindInPath 路由；原生模式立即执行已实例化的原生动作。

保留原生模型对象身份：原生确认回调持有打开窗口时的模型。只在这个对象上回写查询并刷新界面，范围和过滤来自原生当前控件保存后的快照。

原生控件的最近文件过滤历史与当前输入可能不同步；回写前先同步当前文件过滤到原生 FindSettings，再刷新界面，避免刚输入的新过滤条件被历史值覆盖。
