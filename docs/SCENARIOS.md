# 参考速查表场景对应

依据用户提供的《IDEA 常用正则搜索速查表》，所有场景默认限定**同一行**。用户填写的是原始文本，不需要加反斜杠或自己写正则。多值输入按换行拆分，`a,b` 按包含逗号的一个值处理。

| 速查表编号 | 场景 | 插件界面配置 |
| --- | --- | --- |
| 0 | 完整匹配子串 | 包含文本 + 完整词匹配 |
| 1 | A、B、C 同时存在，顺序不限 | 同一组添加三个“必须匹配 → 包含文本” |
| 1 顺序固定 | A → B → C | 按顺序出现；A、B、C 分别占一行 |
| 2 | A 或 B 或 C | 任意一个（或）；三个值分别占一行 |
| 3 | A 且不含 B | 必须匹配 A + 不能匹配 B |
| 4 | A 且 B 且不含 C | 必须匹配 A + 必须匹配 B + 不能匹配 C |
| 5 | A 且不含 B、C、D | 必须匹配 A + 不能匹配“任意一个（或）”，B、C、D 分行 |
| 6 | A 或 B，且不含 C | 必须匹配“任意一个（或）”，A、B 分行；不能匹配 C |

## 语义细节与参考表差异

1. 参考表的总约定为“同一行”，但第 12、14、15、18 节使用 `\s*`，正则本身可能跨越换行。插件按文字约定优先，使用水平空白，**不会跨行**。
2. 参考表的数字正则 `\d{6}` 可能命中 7 位数字中的前 6 位。插件按“固定 6 位数字”的文字意图，检查完整连续数字长度。前后是字母时是否允许命中还受完整词选项控制。
3. 完整词边界比原表默认 Java `\w` 更完整，支持 Unicode 字母、数字、组合符和连接符，避免中文标识符相邻时产生假边界。
4. 字符串包含模板识别转义引号，文本仍限定同一行；它不是 Java 语法分析器，也不解析文本块。
5. “A、B 之间仅空白”对两个输入分别检查完整词，查找 `helloworld` 时应关闭完整词匹配。“A 后紧接 B”先拼接两段文本，再对整体检查完整词。
6. “字段 = 指定值”区分赋值运算符和 `==`；“字段 == 指定值”区分 `==` 和 `===` 等更长运算符。空白限于同一行。
